# Realty Telegram Bot

Рабочий MVP Telegram-бота с закрытой CRM-админкой для объектов недвижимости.

## Что уже есть

- закрытая админка по логину и паролю;
- SQLite-база объектов, медиа, подписчиков, просмотров, заявок и рассылок;
- добавление и редактирование объектов;
- загрузка фото/видео в объект;
- архивирование неактуальных объектов;
- Telegram polling-бот без webhook;
- приветствие и кнопка `Смотреть объекты`;
- выдача актуальных объектов пользователю;
- кнопки `Хочу узнать подробнее`, `Связаться`, `Смотреть еще`;
- сбор заявок через Telegram, телефон или WhatsApp;
- уведомление администратора о новых заявках;
- отправка объекта всем подписчикам из админки;
- отложенные рассылки;
- ежедневная отправка одного непросмотренного актуального объекта в окне 09:00-21:00.

## Поля объекта

Обязательные:

- категория;
- район;
- название здания;
- количество комнат;
- этаж;
- статус: свободно или в аренде;
- площадь;
- цена.

Необязательные:

- санузлы;
- парковка;
- меблировка;
- балкон;
- средняя цена рынка;
- distress;
- original price;
- дополнительное описание.

## Локальный запуск

```bash
cd tg_realty_bot
cp .env.example .env
```

Заполните `.env`, затем:

```bash
set -a
. ./.env
set +a
python3 app.py
```

Админка будет доступна на `http://127.0.0.1:8080`.

## Серверный учёт первого запуска бота

`BOT_METRIKA_ID` и `BOT_METRIKA_MP_TOKEN` включают отправку в отдельный
счётчик бота. Счётчик сайта `YANDEX_METRIKA_ID` остаётся отдельным.
Токен Measurement Protocol хранится только в серверном `.env`.
В счётчике нужна цель с точным идентификатором `bot_start`.

При первом запуске сохраняется запись в `bot_metrika_users`, затем отдельный
поток отправляет серверный просмотр и событие цели. Уже существующие при
подключении подписчики исключаются. Повторные `/start` не отправляют новую цель.
Имена, Telegram ID и контактные данные в Метрику не передаются: используется
случайный постоянный числовой идентификатор.

Прямая рекламная ссылка для проверки: `https://t.me/belowmarketdubaibot?start=yd_{yclid}`.
Бот сохраняет полученный номер клика и передаёт его в URL серверного просмотра.
Атрибуция Директом и пригодность для оплаты за конверсии требуют отдельной проверки
на настоящем рекламном переходе; успешный HTTP-ответ Метрики этого не доказывает.

Статусы очереди: `existing`, `pending`, `sending`, `accepted`, `failed`,
`uncertain`, `expired`. `accepted` означает приём API, не подтверждение атрибуции.
Ожидающие события переживают перезапуск. После тайм-аута или аварии во время
отправки событие помечается `uncertain`: автоматически повторять его нельзя,
поскольку Метрика могла его принять. Требуется сверка с отчётами.
События старше 11 часов помечаются `expired`, чтобы не искажать время запуска.
Проверка очереди: `SELECT status, count(*) FROM bot_metrika_users GROUP BY status;`.

Тесты: `python3 -m unittest test_bot_metrika.py`.

## Публичные URL медиа

Фото и видео отправляются Telegram по публичным URL. Поэтому на VPS нужно указать:

```bash
PUBLIC_BASE_URL=https://your-domain.com
```

И настроить nginx так, чтобы домен проксировал админку на локальный порт приложения.

## Пример systemd

```ini
[Unit]
Description=Realty Telegram Bot
After=network.target

[Service]
WorkingDirectory=/opt/tg_realty_bot
EnvironmentFile=/opt/tg_realty_bot/.env
ExecStart=/usr/bin/python3 /opt/tg_realty_bot/app.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## Минимальный nginx proxy

```nginx
server {
    server_name your-domain.com;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

TLS лучше подключить через `certbot`.
# Ссылки Яндекс Директа и реферальные уведомления

Для кампании с реферальным кодом `source_d2d9` используйте в Директе:
`https://t.me/belowmarketdubaibot?start=yd_{yclid}_ref_source_d2d9`

Бот получает ID клика и существующий реферальный код. Название кампании и источник
берутся из записи реферальной ссылки; посещение попадает в её статистику,
администратор получает обычные поля и ID клика. Старые `ref_...` ссылки продолжают работать.
Вариант `yd_{yclid}` без кода тоже присылает уведомление, но кампания будет «Не указана».
После подстановки параметр start должен занимать не более 64 символов.
Повторные запуски дают уведомления как раньше; цель Метрики отправляется только для первого запуска нового пользователя.
Передача yclid в Метрику не подтверждает атрибуцию: её нужно проверить по реальному клику из рекламы.

## Каталог: языки, валюты и оффплан

- Все рабочие цены в базе и админке — AED. При первом запуске новой версии
  старые `*_price_usd` пересчитываются в новые `*_price_aed` один раз. Старые
  столбцы оставлены для совместимости схемы, повторный запуск не конвертирует цены снова.
  Перед обновлением рабочей базы сохраните её резервную копию.
- На сайте, в мини-приложении и в карточках бота доступны AED и USD.
  Курс отображения: 1 USD = 3.6725 AED, без банковских комиссий.
  Источник: [Центральный банк ОАЭ](https://centralbank.ae/umbraco/Surface/Exchange/GetExchangeRateAllCurrency).
  Бюджет в USD пересчитывается в AED до фильтрации; сохранённая цена не меняется.
- Каталог и фильтры бота: релевантность, популярность, цена по возрастанию/убыванию,
  «По скидке к рынку», «От застройщика», «Только дистресс». Сортировка по скидке
  идёт от наибольшего процента к наименьшему; объекты без данных — в конце.
  Дистресс определяется только явной отметкой в админке. Популярность — число открытий карточки на сайте и запросов
  подробностей в боте; автоматические отправки не считаются просмотрами.
  Релевантность каталога: точное совпадение названия, совпадение начала названия,
  затем другие совпадения; при равенстве — обновлённые объекты первыми.
- Для Studio, 1BR, 2BR, 3BR сохраняются стартовая/максимальная цена и необязательная
  площадь с единицей измерения. Максимум можно менять вручную. Автоподсказка берёт
  среднюю разницу по той же конфигурации, если есть минимум 5 вручную подтверждённых
  диапазонов других проектов. Иначе используется предварительное +100 000 AED.
  Это эвристика по данным каталога, не внешняя рыночная статистика. Автоматические
  оценки исключены из статистической выборки и обозначены на сайте/в боте.
- Средняя рыночная цена и процент ниже рынка необязательны. Введённый вручную
  процент имеет приоритет; если его нет, процент вычисляется из средней цены.
- Первый `/start` запрашивает RU/EN. Источник рекламного перехода фиксируется сразу;
  ссылка на конкретный объект сохраняется до выбора языка. Язык и валюта сохраняются
  у подписчика, каталог и меню бота открываются с его настройками.
- Комментарий оффплана обязателен на русском и английском. Для русского описания
  вторички, рассрочки или срока сдачи требуется английский перевод. Автоматического
  перевода нет: английский текст вводит редактор. Старые записи без перевода не
  показывают русский комментарий в английской версии; перед публикацией проверьте их.
- Свободные и сегментные рассылки имеют отдельное английское поле. Старые русские
  рассылки без перевода пропускают английских подписчиков. Автоматические предложения
  и рассылки не отправляются подписчикам до выбора языка.

Проверки: `python3.11 -m unittest discover -p 'test*.py' -v`.
`test_catalog_features.py` использует временную базу и заглушки Telegram: проверяет
миграцию, расчёты, фильтры, валидацию, языки, валюты и продолжение ссылки после выбора языка.

Сортировки на сайте видны отдельной строкой и применяются сразу при выборе.
Переключатель AED/USD расположен рядом с RU/EN; выбранная валюта сохраняется
в адресе страницы и при перезагрузке. Поля комментариев вторички подписаны
«Комментарий / описание (русский)» и «Комментарий / описание (English)».


## Скорость Telegram и тексты бота

Telegram API использует IPv4: IPv6-маршрут VPS к Telegram не работает и добавлял
около 30 секунд к отдельным запросам. TLS по-прежнему проверяет api.telegram.org.
Остальные HTTP-клиенты не изменены.

Уведомления администраторам сохраняются в admin_notifications и отправляются
отдельным worker, чтобы не задерживать ответы клиентам и веб-заявки. Очередь
сохраняется при перезапуске. Ответ 429 повторяется с retry_after (до 5 попыток).
Неоднозначные тайм-ауты не повторяются, чтобы избежать дублей: запись остаётся
со status=failed для проверки. Успешно отправленные записи удаляются.

В боте остаются фильтры; сортировка доступна только в каталоге. Старые кнопки
сортировки переходят к выбору комнат, сохранённый filter_sort больше не влияет
на выдачу бота. BOT_DESCRIPTIONS содержит единое двуязычное описание: сначала
английский текст, затем русский, независимо от языка Telegram;
публикация выполняется через setMyDescription для default, ru и en с проверкой
getMyDescription. Приветствие после выбора языка короче и ведёт к каталогу/фильтрам.

Каждый /start, включая повторный, сначала предлагает выбрать язык. Затем приходит
приветствие на выбранном языке; при ссылке на лот следом приходит карточка лота.
Описание до старта разделено заголовками ENGLISH / РУССКИЙ и линией.
